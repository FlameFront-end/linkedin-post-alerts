# Открытые вопросы и ограничения

## Блокирует реальный сбор

- Не проверено, работает ли сейчас keyword search постов через Voyager/GraphQL на сессии пользователя.
- Чтение постов известных авторов и поиск по словам — разные возможности, проверять отдельно.
- Как безопасно передавать/обновлять сессию, где запускать сервис и какие лимиты допустимы.
- Нет обещания полного охвата или задержки в несколько минут. Нужен замер publishedAt → firstSeenAt.

## Перед постоянной эксплуатацией

- Правила фильтрации — стартовая эвристика. Возможны ошибки отрицаний, контекста, смешанных языков.
- Что значит «русская»: язык текста, язык команды, требования или география? Пока язык — метка приоритета.
- Пока одно уведомление на пост, в нём может быть несколько направлений. Разделение подборок на вакансии позже.
- Нет OCR, обработки PDF, комментариев о закрытии вакансий и смыслового удаления дублей между авторами.
- Telegram не предоставляет ключ идемпотентности sendMessage: при падении после отправки до фиксации возможен дубль.
- Три сервиса используют одну БД/роль локально. В production нужны отдельные роли и права; это сознательный компромисс каркаса.
- Очередь хранит ключи дедупликации бессрочно. Политика retention/архивации ещё не выбрана.
- Health — техническая готовность; успешность и свежесть реального сбора нужно измерять отдельно.
- Авторизованный сбор противоречит правилам LinkedIn и может вызвать ограничения аккаунта.

Не добавлять модель к каждому посту до измерения качества правил и бюджета.

- Live Telegram с mock-источником запрещён, Compose пока фиксирует безопасные режимы.
- Dry-run завершает задания: автоматического переноса dry-run истории в live нет.
- Новая редакция поста с прежним ID не обрабатывается повторно; нужен отдельный дизайн edit events.
- RU пока только визуальная метка, без сортировки приоритетов.
- Локальные контейнеры и типизация проверяются; внешние GitHub Actions здесь не запускались.

- Telegram cooldown общий только внутри одного экземпляра notifier. Для нескольких реплик
  требуется общий rate limiter по bot/chat. Пока запускается одна реплика.
- Миграции проверяются по имени, без checksum; применённые SQL-файлы не редактировать.

## Обновление: HTTP-адаптер добавлен

- Реализован прямой GET profileUpdatesV2 и конфигурируемый keyword request template.
- Нет живой сессии: корректность запросов и декодера пока подтверждена только синтетическими тестами.
- Search-карточки без полного UpdateV2 сейчас отвергаются; может потребоваться hydration.
- URN профиля задаётся вручную, резолвер public URL ещё не реализован.
- Пагинация ограничена, durable cursor отсутствует: полный охват при большом потоке не обещается.
- Декодер выбирает первую найденную коллекцию; если реальный ответ содержит несколько кластеров,
  нужно адаптировать выбор и обход по живой структуре.
- Автор без actor.name помечается LinkedIn author. Нужно проверить actual author refs.
- Дата без createdAt вычисляется из activity ID, нужна сверка с интерфейсом.

## После независимого ревью

Часть исторических замечаний выше исправлена. Актуальный статус по пунктам — REVIEW_RESPONSE.md.
Без сессии остаются непроверенными реальный endpoint, paginationToken, CSRF и структуры ответов.
Keyword search имеет только экспериментальный транспорт, полноценного поискового декодера нет.
