# Файловые журналы

Рабочая папка: `.local/logs/` внутри проекта. Она исключена из Git и Docker build context. Файлы находятся на компьютере, а не в слое контейнера.

```text
.local/logs/
  collector/collector-YYYY-MM-DD.jsonl
  processor/processor-YYYY-MM-DD.jsonl
  processor/queue-YYYY-MM-DD.jsonl
  notifier/notifier-YYYY-MM-DD.jsonl
  notifier/queue-YYYY-MM-DD.jsonl
  ocr/ocr-YYYY-MM-DD.jsonl
  migrate/migrate-YYYY-MM-DD.jsonl
  diagnostics/diagnostics-YYYY-MM-DD.jsonl
  reports/report-<UTC timestamp>.json
```

JSONL содержит одну JSON-запись в строке. Все даты UTC. Поля: timestamp, service, event, level, pid, traceId цикла, requestId HTTP-запроса и безопасные параметры события. Для связи между процессами используются postId, revision, vacancyId и jobId; traceId относится к конкретному циклу конкретного процесса.

## Что записывается

- Collector: начало/конец/пропуск цикла, состояние карантина Jobs, фактический запрос и HTTP-статус, размер ответа и длительность, ожидание лимита, отказ защиты и код ошибки, каждая разобранная страница и состояние пагинации, наблюдённый ID поста и постановка новой версии в очередь.
- Processor: получение задания и номер попытки, отбрасывание устаревшей версии, причина отбора каждой позиции, язык и роли, повтор вакансии и новая версия, запрос и результат OCR, повтор обработки и ошибки БД.
- Notifier: фильтрация/устаревшее сообщение, начало отправки, ответ Telegram, пауза после ошибки, успешная отправка и запись квитанции, повтор подтверждения БД.
- OCR: доступность, попадание в кеш, начало/конец распознавания, размеры и длительность, HTTP-статус картинки, ошибки. Изображение идентифицируется хешем.
- Queue: вставка/повтор, получение, завершение, возврат, потеря аренды, повтор/постоянный отказ.
- Миграции: начало, уже применённые миграции, применение и ошибка.
- Диагностика: запуск проверки, факт одиночной проверки и отказ. Проверка без параметров по-прежнему не обращается к LinkedIn.
- Жизненный цикл: запуск, завершение, изменение readiness, heartbeat раз в минуту, необработанное исключение и предупреждение Node. Ошибки сохраняют машинный код и причину, без произвольного текста провайдера.

Квоты и обычные защитные паузы пишутся как info. Отказы провайдера и неожиданные ошибки — warn/error. События внутри транзакции описывают попытку; post_processed и delivery_committed подтверждают её успешное завершение.

## Размер и секреты

- Ротация по дню и 5 MiB, до 3 резервных файлов за день для каждого вида журнала; срок хранения 7 дней. Очистка выполняется при записи после смены дня.
- Папки имеют права 700, файлы — 600. Docker запускает приложения с LOCAL_UID/LOCAL_GID владельца, чтобы записи оставались доступны на компьютере.
- Cookies, токены, пароли, заголовки, payload, HTML, полные тексты постов, письма и произвольные ошибки в журналы не записываются. Ключи с такими данными редактируются; URL и email в строковых полях маскируются. Не добавлять в log произвольные тела ответов и stack trace.
- stdout/stderr дополнительно остаются в Docker с ротацией 10 MiB × 3 для каждого контейнера, включая PostgreSQL. Журнал PostgreSQL доступен через Docker, его SQL/параметры специально не включаются в прикладные JSONL.
- Если диск/права мешают записи, приложение продолжает работу, а Docker stderr получает log_file_failed не чаще раза в минуту. Такой случай нужно исправить, иначе на диске будет пробел.

## Команды

Перед первым развёртыванием на новом компьютере:

```sh
npm run logs:init
```

Проверить **все** текущие и ротированные JSONL, получить сводку и локальный /status:

```sh
npm run logs:report
```

Команда выводит путь к отчёту. Он содержит счётчики событий, последние записи сервисов, до 50 свежих warn/error, некорректные строки и состояние источников/очереди. Хранятся последние 20 отчётов. Она не отправляет запросы к LinkedIn и не запускает повторную отправку Telegram.

Посмотреть конкретный файл, например collector:

```sh
tail -n 100 .local/logs/collector/collector-2026-11-09.jsonl
```

Журналы начинают существовать с момента установки. Успех или ошибка пока не случившегося действия не симулируются в рабочей очереди ради логов; соответствующие ветки проверяются тестами.
