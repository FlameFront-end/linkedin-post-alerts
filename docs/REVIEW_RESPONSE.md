# Ответ на независимое ревью

Исходный отчёт `CLAUDE_REVIEW.md` сохранён отдельным коммитом без изменения выводов.

## Исправлено

- К1: обработка ошибок на уровне цели. 400/404/5xx и сетевой сбой не мешают другим целям.
  Потеря общей сессии/429 останавливают все запросы; неизвестный формат отключает только цель до перезапуска.
- К2: keyword search — экспериментальный транспорт с шаблоном, а не готовый поиск.
  (Устарело: флаг `experimentalKeywordSearch` больше ни на что не влияет, см. GLOBAL_SEARCH.md.)
  Полного декодера EntityResultViewModel и hydration пока нет. Ошибка keywords не отключает авторов.
- К3: UpdateV2 без текста пропускается со счётчиком skippedNoText; неизвестные карточки остаются ошибкой.
- К4: Telegram 401/403/404 и неоднозначный 400 приостанавливают sender до исправления настроек/перезапуска.
  Текущее задание возвращается pending без расхода attempts, остальной backlog не забирается.
  Permanent оставлен для известных ошибок сообщения. Добавлена адресная replay-команда с preview.
- С1: авторская страница 2 запрашивается только при наличии metadata.paginationToken предыдущей страницы;
  токен передаётся в запрос. Его реальную форму и расположение всё ещё надо проверить на аккаунте.
- С2: текст репоста включает текст оригинала, ID/автор/дата сохраняются внешнего activity.
- С3: добавлены Docker healthchecks для всех трёх сервисов; notifier readiness отражает блокировку.
  Внешнего мониторинга и оповещения владельцу пока НЕТ. Unhealthy не перезапускает контейнер автоматически.
- С4: отправка и подтверждение разделены. Ошибка complete повторяет только подтверждение до 3 раз.
  После исчерпания — delivered_not_committed без fail. Аренда затем истечёт и дубль всё ещё возможен.
  Предложение «просто не вызывать fail» само по себе не устраняет дубли, лишь меняет время повтора.
- С5: optional session.userAgent позволяет использовать фактический User-Agent своего браузера.
  Дополнительные x-li-* заголовки не выдумывались; необходимость остаётся предметом live-проверки.
- С6: linkedin:check выводит результаты по целям, счётчики страниц и безопасные характеристики образцов.
  Ноль результатов обозначается empty; ошибки целей дают ненулевой exit code.
- С7: ошибки настроек разделены по безопасным причинам: settings_read/schema, session_read/schema/permissions.
- С8: migrate читает .env при наличии; replay умеет восстановить выбранный dead job.

## Остаётся открытым

- Первый live-прогон: глобальный поиск с низкими лимитами, Telegram dry-run (PRODUCTION.md).
- Актуальность endpoint, CSRF, queryId, структуры и полнота текста не проверены на реальном аккаунте.
- Реальный поиск новых авторов/вакансий по словам ещё не готов.
- Нет exactly-once Telegram. При успешной отправке и длительном сбое БД/падении остаётся окно дубля.
- Классификатор остаётся эвристикой: неоднозначность «ищет работу» в рекрутерском тексте не исправлялась
  отдельным усложнением без корпуса реальных примеров.
- Нет автоматического оповещения об остановке collector и общего rate limiter нескольких notifier.

## Как восстановить выбранное задание

`npm run queue:replay -- notification 123` — только preview.
`npm run queue:replay -- notification 123 --apply` — вернуть выбранный dead job в pending.
Заменить ID, проверить причину ошибки, затем перезапустить notifier с исправленными настройками.
