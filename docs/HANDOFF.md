# Передача проекта: LinkedIn Post Alerts

Проект: `<project-root>`.

## Что готово

Три отдельных сервиса на TypeScript/Express: collector, processor, notifier.
PostgreSQL хранит задания и результаты. Есть дедупликация по ID поста, аренда заданий,
повторы и dead jobs. Обработка поста и создание уведомления атомарны.
Есть mock-источник, эвристический фильтр Frontend/DevOps, Telegram sender с dry-run,
Docker Compose, миграции и CI-конфигурация.
Playwright, платные API и модель на каждый пост не используются.

Реальный LinkedIn не реализован и не проверен, Telegram-сообщения не отправлялись.
Это рабочий каркас с демонстрационным потоком, не готовый сборщик вакансий.

## С чего продолжить

1. Прочитать `docs/OPEN_QUESTIONS.md` и `docs/LINKEDIN_ADAPTER.md`.
2. Проверить на сессии пользователя прямой HTTP-поиск **постов**, отдельно — посты рекрутера.
3. Реализовать PostSource, обеспечить постраничность и checkpoint.
4. На реальных примерах настроить классификацию, затем подключить Telegram.

Cookies не передавать через чат, хранить вне Git. Ни один сторонний Voyager SDK не установлен.

## Важные ограничения

RU пока визуальная метка приоритета; нет географической фильтрации, OCR, извлечения зарплаты,
семантических дублей между авторами и обработки изменений старого поста.
Telegram может получить повтор после сбоя между отправкой и подтверждением.
Rate limiter пока локален одному notifier. Общая БД/роль — локальный компромисс,
перед production нужно ограничить права сервисов. Все эти пункты раскрыты в OPEN_QUESTIONS.
